// The unresolved T# bindings are FIXED (2026-08-03, commit "an SMRD literal
// offset counts dwords, not bytes"). Every binding that failed was loaded

// THE HEAP, measured (2026-08-03). Over 40 s the title makes 1,758,140
// allocations and 1,229,146 frees, i.e. it really does retain a large share of
// what it takes -- this is not "nothing is ever freed". The deallocator is
// eboot+0x12af0 (rdi = pointer, dispatched through the allocator's vtable slot
// +0xa8, falling back to 0x19a50 to find the owner); profile it with the `:c`
// suffix, which ranks by call count instead of by a first argument that is not
// a size:
//   +DELTA_HEAP_PROF=0x201400012820,0x201400012af0:c
// What that still cannot say is WHICH site's memory is retained, because a
// free is called from a destructor rather than from the allocating code. The
// tool that would settle it is live-bytes-per-site, which needs the allocation
// pointer and so needs the allocator's RETURN hooked, not its entry.
//

// THE FRAME, MAPPED (2026-08-04, with tools/gpu_capture.py -- see
// delta/gpu/DEBUGGER.md). SotC is a deferred renderer: shadow cascades ->
// main-view Z-prepass (reverse-Z, clear 0, ZFUNC=GEQUAL) -> 7-MRT G-buffer
// re-drawing the same geometry with ZFUNC=EQUAL -> deferred lighting (samples
// the G-buffer AND the depth buffer it has bound) -> a full-screen compute
// resolve that publishes the scene colour -> half-res post -> tonemap -> UI
// layer -> composite. Three defects were deleting most of that and are fixed:
// the 16 MiB vertex ring declined 83 draws a frame (now 512 MiB), the EQUAL
// depth test rejected the scene because our two vertex shaders are not
// bit-identical (DELTA_GPU_RELAX_ZEQUAL, on by default), and the lighting pass
// was declined as self-sampling (now bound DEPTH_READ_ONLY).
//
// The integer G-buffer is now implemented (DELTA_GPU_INT_RT=1, opt-in): all
// seven targets carry real world geometry, where two of them used to read
// exactly zero. The next break is one stage on -- the deferred lighting pass
// discards nearly every pixel because it samples its material/stencil ID from
// the draw's own stencil surface (0x805fe50000, R8_UINT), and we have no
// stencil-aspect sampled view, so that binding resolves to an unrelated colour
// RT. Needs ResolveSampledStencil + a VK_IMAGE_ASPECT_STENCIL_BIT view.
//
// WHY IT WAS BLACK BEFORE THAT: the G-buffer is an INTEGER buffer.
// CB_COLORn_INFO says FORMAT=COLOR_32 / COLOR_32_32 with NUMBER_TYPE=UINT for
// 6 of the 7 targets, and CB_SHADER_MASK=0x1331111 agrees (one component per
// 32-bit target). We create them B8G8R8A8_UNORM, so two read back exactly
// zero and the scene the compute resolve publishes is black. The integer path
// is implemented but gated off -- with it on the title stops issuing the
// G-buffer pass altogether, which is not yet understood.
// +DELTA_GPU_INT_RT=1                    integer colour targets (UNVALIDATED)
// +DELTA_GPU_RELAX_ZEQUAL=0              restore the strict EQUAL depth test
// +DELTA_GPU_VBRING_MB=<n>               override the vertex ring

// THE 16x16 SRGB TEXMISS, CHARACTERIZED (2026-08-06): the one persistent

// T#'s word0 (base) is zero while words 1-3 are valid; the miss report

// descriptors at wave launch, long after. The writeback-flush fix (commit
// "flush pending compute writebacks before the replay reads a descriptor")
// closes the adjacent staleness class but not this. Impact: one LUT samples
// white. Candidate fix: defer/retry resolution for base==0-but-plausible T#s
// at the NEXT draw using the same slot, or resolve against the slot at
// submit-end rather than record time.

// THE COMPUTE WRITEBACK REVERTS THE CPU, MEASURED (2026-08-07). Separate from

// compute. The writeback now publishes only the words the dispatch changed
// (compared against a shadow of the staged bytes) and adopts the CPU's word
// otherwise, so staging, shadow and guest all agree again when it returns.
// +DELTA_GPU_CS_WB_FULL=1   restore the copy-everything behaviour (A/B)

// PAST THE TITLE (2026-08-06): the menu opens and renders readable entries
// (New Game / Settings / Image Gallery, difficulty select) on current
// builds; the earlier "solid glyph blocks" existed only pre-dedupe.
//
// THE NEW-GAME CRASH: THE 2026-08-06 DIAGNOSIS WAS BUILT ON STALE REGISTERS
// AND IS WITHDRAWN (2026-08-07). It read "a fiber returned its stack to the
// pool and kept running on it" out of rax=0x830a79fbd0 / rsp=0x830a79fb10,
// registers that were never the fault's. On aarch64 the dump printed FEX's
// in-memory CPUState, which the JIT only spills at block boundaries and which
// FEX's syscall op fills with just the subset the syscall ABI reads. Two facts
// settle it: rdi/rsi in all four historic dumps are VERBATIM the thread's last
// syscall arguments (sys_umtx_op(0x200003420,0x12) -> rdi=0x200003420,rsi=0x12;
// sys_batch_map(0x10,0x10) -> rdi=0x10,rsi=0x10), and si_addr never equalled
// rax-8 as `mov rcx,[rax-8]` requires. The dump now reads the JIT signal
// context (guestGregsFromSignal) and prints a corroboration line -- every new
// dump says "fault = rax-8". The maps block lied too: it slurped
// /proc/self/maps into 1 MiB and silently truncated, so all four dumps reported
// /dev/nvidiactl as the fault's neighbour. It streams now and says GAP.
// libSceFiber is NOT implicated: that census page was picked from the stale rax.
//
// WHAT THE CRASH ACTUALLY IS (measured 2026-08-07, three crashes):
// the faulting function (prologue 0x48a70) inserts a chunk into the allocator's
// SIZE-ORDERED FREE TREE (dlmalloc-shaped: state+0x80 is the head and the loop
// sentinel, a node is chunk+0x10, its size is at node-8, children at node+0x00
// and node+0x08, dup-list at +0x10/+0x18, parent|colour at +0x20). The tree
// holds STALE CHILD LINKS pointing at chunks that have been handed back out and
// refilled with live data (recognisable 40-byte and 32-byte record arrays of
// packed descriptors -- 0x00XX7080deYYYYYY / 0x180272040000YYYY). The walk then
// reads that data as nodes and dies a few steps later on an unmapped "node".
// The victim is the SAME node every run: 0x8052e00020, size 0xd0, and the split
// inside it is exact -- +0x10/+0x18/+0x20 (dup list and parent, written by
// SCALAR stores) are correct, while +0x00/+0x08 (the two children) are stale.
// Crash timing is NOT deterministic (script step 86 / 48 / 8), so it is a race
// and single-run A/B proves nothing; one run corrupted into a 4-thread
// sched_yield livelock instead of a fault.
// The walk is now a crash-time diagnostic: it replays the insert, flags the
// first node that is no longer a free chunk, names the field holding the stale
// link and prints the census command for it.
//
// RULED OUT BY MEASUREMENT, not by argument:
//  - Compute staging writeback: "no compute staging range covers the stale
//    link" for every stale link in two independent crashes (the crash handler
//    asks gpu::DescribeCsRangeCovering directly).
//  - FEX vector TSO (+DELTA_FEX_VECTOR_TSO=1): reproduces with an identical
//    signature (same node, children stale, parent intact). Worth knowing the
//    insert publishes both children with ONE `vmovups [rsi],xmm0` at 0x48b46,
//    which made this the best-looking theory; it is still wrong.
//  - Unaligned-atomic backpatching: 0 of the 1264 eboot backpatch sites fall in
//    the allocator (0x47000-0x4b000), its entry (0x12000-0x13000), its caller
//    at 0x16ac3e, or the job system (0x38000-0x3a000).
//  - Any non-guest writer: a from-boot census of the page,
//    +DELTA_GUEST_WHIST=8052e00000:1000:200, names nine writers over 120
//    reports and every one is guest allocator code (0x48b3a, 0x48dfb, 0x499cc,
//    0x4a0b7, 0x4a16e, 0x4a1bf, 0x4a1f5, 0x4a358, 0x4a388 -- insert plus the
//    rebalance at 0x4a040). ZERO unattributed (emulator-side) writes.
// So the corrupted words are written only by the title's own allocator. What is
// left is (a) our JIT mis-executing one of those nine sites, or (b) two guest
// threads inside the allocator at once -- a half-finished red-black rebalance
// seen by a second walker has exactly this shape (children wrong, parent
// right). The crashing thread runs on a fiber (backtrace ends at
// libSceFiber+0x2f6, through the job system at 0x39ab6/0x38ad2) and its syscall
// history is almost entirely MUTEX_WAIT/MUTEX_WAKE on one lock, 0x200003420,
// which is the contention this allocator is under.
//
// (b) CANNOT BE SETTLED BY SAMPLING -- priced, not guessed (2026-08-07).
// DELTA_RIPRACE (see the diag commit) signals every guest thread and has it
// reconstruct its own guest rip from its signal context, so it reports where
// threads REALLY are, and counts rounds with two or more inside a range.
// Measured over 410k rounds / 8.1M thread-answers on the allocator core
// 201400047000-20140004b000: 199 rounds caught ONE thread inside, two rounds
// caught two (0x48f07 `mov [r13+r15+0x10],r13` and neighbours -- chunk
// bookkeeping, not a lock spin), and the two samples in those rounds were 2832 ns
// and 5760 ns apart. ZERO pairs within a microsecond, i.e. nothing that shows
// simultaneity rather than adjacent serialised access.
// The duty cycle is what kills the method: p(a thread-sample lands inside) =
// 2.4e-5, so with NO exclusion at all the expected number of simultaneous pairs
// in 410k rounds is 0.046. Observing zero is exactly what an unlocked section
// produces. One expected detection needs 8.9e6 rounds (2.5 h at 1 ms); a
// decisive ten needs a day. Narrowed to the insert + rebalance alone,
// p = 2.6e-6 and it needs 7.6e8 rounds. Do not re-run this hoping for an answer.
//   +DELTA_RIPRACE=1:201400047000-20140004b000        (allocator core)
//   +DELTA_RIPRACE=1:201400048a70-201400048b64,20140004a040-20140004a205
//
// THE DETERMINISTIC TEST, RUN (2026-08-07): CONCURRENCY IS REAL BUT IS NOT THE
// CAUSE. DELTA_SOTC_ALLOCLOCK detours the allocator entries (0x12820 alloc,
// 0x12af0 free, 0x48a70 free-tree insert) and holds a native mutex across each
// call, so every call is observed instead of one in 40000, and a failed try_lock
// names a second thread already inside.
//   +DELTA_SOTC_ALLOCLOCK=2   one mutex PER SITE -- the measurement
//   +DELTA_SOTC_ALLOCLOCK=1   one SHARED mutex   -- the mitigation (~3x slower)
// Mode 2, one boot into the menu:
//   alloc(0x12820)          4809876 calls,  366064 contended
//   free(0x12af0)           1505986 calls,    7103 contended
//   freeTreeInsert(0x48a70)  184030 calls,       5 contended   <-- a violation
// Five is real: 0x48a70 mutates the tree, takes no lock itself and makes exactly
// one call (the rebalance at 0x4a040), so it must be entered with exclusion
// already held. Two threads inside it is the exclusion failing, not contention.
// Mode 1 then drives that to 0 over 194503 inserts -- and THE CRASH STILL HAPPENS,
// same rip, same node 0x8052e00020, same stale child[0] into 0x80577xxxxx.
// (A first mitigation attempt used mode 2 by mistake and proved nothing: per-site
// locks let a thread in 0x12820 meet a thread in 0x12af0 over the same tree.)
//
// WHERE THAT LEAVES IT (corrected 2026-08-07 -- see the withdrawal below):
// concurrency is real but disfavoured as the cause, and no emulator-side writer
// touches the pages. The cause is still open.
//
// WITHDRAWN: "the corrupted node is the SAME every crash, so this is a
// deterministic miscompile". That was true of five crashes and false of the
// sixth. Runs 1-5 all tripped on node 0x8052e00020's child[0]; run 6 tripped on
// node 0x807bbe6f90's child[1], pointing at 0x8052ec4170, with 0x8052e00020 not
// even on the walk. Node identity was a small-sample artifact and the
// determinism argument built on it does not stand. The victim varies; what is
// stable is only the shape (a link that still points at a chunk which has been
// handed back out and refilled).
//
// DELTA_SOTC_TREEWATCH=1 validates one node's child[0] on both sides of every
// allocator call (entry clean + exit dirty names the call containing the store).
// It reported 16070962 checks, 2 bad-on-entry, 0 transitions -- which says
// nothing, because it was aimed at 0x8052e00020 and that run's victim was a
// different node. A single-field watch is the wrong instrument once the victim
// moves. Two lessons are baked into the code and worth keeping:
//   - the node does not exist at boot, so the watch must stay disarmed until its
//     page is mapped, or the first allocator call kills the process (it did);
//   - it must only judge the field while the node is ITSELF a live free chunk,
//     otherwise pre-membership junk reads as corruption (124 phantom hits).
//
// ALSO FIXED: chunk sizes are 8-GRANULAR, not 16. The allocator masks its size
// word with ~7, and run 6 contained a real free chunk of 0x158, which the
// crash-time walker's 16-alignment test flagged as "no longer a free chunk" --
// blaming the wrong link. Both the walker and the watch now test 8-granularity.
// Any earlier walk output that broke at a non-16-aligned size should be re-read.
//
// LATENT, NOT THIS CRASH (for whoever wants it): the guest pthread mutex at
// 0x200003420 failed to exclude 5 times in 184030 free-tree inserts under
// contention (DELTA_SOTC_ALLOCLOCK=2). Serialising it away does not fix the New
// Game crash, so it is not the cause here -- but a userland-CAS or umtx wake that
// leaks mutual exclusion is a latent bug for every title on this backend and
// deserves its own chase. Start at the 27 unaligned-atomic backpatch sites
// clustered in 0x270db-0x2719b of the module at 0x200200000000, since FEX
// documents that backpatching makes even ALIGNED accesses through that site
// non-atomic (HalfBarrierTSOEnabled).
//
// THE HOST-MUTEX EXPERIMENT WAS NEVER SERIALISING THE ALLOCATOR (2026-08-07).
// A scan of every direct call in the eboot targeting the allocator core
// (0x47000-0x4b000) finds 22 EXTERNAL entry points, called from all over the
// image -- 0x8c536, 0x33710, 0x25707b, 0xa4675c, 0x443d8, 0x4bdea and more. So
// locking 0x12820 + 0x12af0 covered 3 doors of 22+, and the earlier conclusion
// "serialising the allocator does not stop the corruption, so it is not a race"
// IS WITHDRAWN. The gap recorded at the time was wrong too: 0x12350 is 31 bytes
// that decrement a scope depth counter (`dec dword [rax+0x400]`) and free nothing,
// so there is no bulk-free path there, and its PIC prologue is 13 bytes -- not
// detourable anyway.
//
// LOCK THE MUTATORS INSTEAD. All 11 call sites of the tree-mutating functions live
// inside the core, so serialising those covers every door at once, and it is
// narrower and cheaper than the API lock (2 fps against 1.3). The five mutators:
//   0x48a70 treeInsert     cut 16      0x497f0 treeRemove    cut 16
//   0x4a040 treeRebalance  cut 14      0x4a210 treeFixup     cut 15
//   0x48c80 treeCoalesce   cut 17
// 0x48c80 was missed by every earlier experiment: census site 0x48dfb lives there,
// and it was mis-attributed to 0x48c70, a 9-byte leaf whose `ret` is followed by
// SEVEN nops -- one short of the eight the function-boundary scan wanted. It is the
// most contended site of all (6 contentions in its first 152 calls).
// 0x4a040 uses rbp as a NODE pointer (loaded from rdx at 0x4a075), so its
// [rbp+0x20] accesses are node fields, not stack args, and a detour is safe.
//
// MEASURED (+DELTA_SOTC_ALLOCLOCK=1 +DELTA_SOTC_TREEWALK=4096):
//   treeInsert     290885 calls, 309 CONTENDED     treeRemove   103024 calls, 42
//   treeRebalance   70316 calls,   0               treeFixup     29217 calls,  0
// 351 events, against 5 for the old three-site configuration. Rebalance and fixup
// show 0 because they are called from inside insert/remove, which already hold the
