// SHADOW OF THE COLOSSUS (CUSA08809, PS4)
// Boots, loads its modules, returns from LoadInitialWorld and runs the main
// loop with the renderer live, and RENDERS ITS INTRO: the "Sony Interactive
// Entertainment presents" card and the JAPAN Studio logo both come up with
// correct glyphs and colour (2026-08-03, after the SMRD literal-offset fix
// below). 131-146 unique shaders recompile, none declined.
// The blocker is memory: the world content streaming behind the main loop
// burns the engine's whole 1 GiB CPU heap and it then walks off its own
// "no free block" sentinel at eboot+0x1a371, about ten seconds in.
// DELTA_GUEST_NULLGUARD=1a371:rax:4 makes that survivable (a diagnostic, not
// a fix -- the memory it was denied is still denied).

// The world-load spin hammers sched_yield (6.4M calls in 20 s), which our
// default maps to a pause; a real host yield lets the load finish first.
// +DELTA_SCHED_YIELD_REAL=1

// Cap read throughput so the streaming loader cannot outrun its own finalizer.
// +DELTA_IO_MBPS=60

// Watch the CPU heap's free map drain (address from the crash's r9).
// +DELTA_GUEST_POPCNT=8000940af8:5e00:1000

// Watch the resource queues drain 16294 -> 0 (the load itself completes).
// +DELTA_GUEST_SUMWATCH=201402ee2d00:110:28:10:1000

// The unresolved T# bindings are FIXED (2026-08-03, commit "an SMRD literal
// offset counts dwords, not bytes"). Every binding that failed was loaded
// with the wide `s_load_dwordx8 s[4:11], s[20:21], 0x218` form, and every one
// that resolved used the 8-bit immediate form; we were reading the literal as
// a BYTE offset, so each descriptor landed a quarter of the way into its
// table and decoded out of the neighbouring constants (the giveaway: the
// "descriptors" were 59.94, 0.0167, +/-1.0 -- a cbuffer). TEXMISS now prints
// the descriptor's source address and the memory behind it, and reports 0
// misses a run (was 64, the log cap).
//
// Separate real bug found the same day, NOT the menu's cause: all 48 of the
// CE RAM loads above are dropped. CcbGuestRange floors at 0x1000000000, but
// the source is 0xfe0000c00 -- inside the Gnm driver area (0xfc0000000+1GiB,
// which the guest devmaps at 0xfe0000000). CE RAM is never initialised. Inert
// for SotC (nothing ever dumps CE RAM back to memory here), latent for any
// title that drives its CUE through the CE ring.
// +DELTA_GPU_CETRACE=1 +DELTA_GPU_CETRACE_MAX=200   every CE RAM packet
// +DELTA_GPU_PRESENT_ADDR=0x804e660000   the busiest offscreen target
// +DELTA_GPU_PSWHITE=1                   force the fragment colour
// +DELTA_GPU_PSTEX=2 +DELTA_GPU_PSTEXSCALE=50   export a sampled texel
// +DELTA_GPU_RTTINT=1                    tint the sampled source
// +DELTA_GPU_BINDTRACE=0x804390f000      per-binding bucket + read barrier
// +DELTA_GPU_TEXMISS=1                   unresolved T# bindings, per PS
// +DELTA_GPU_DRAWSEQ=260 +DELTA_GPU_DRAWRT=1 +DELTA_GPU_WHYDROP=1

// THE HEAP, measured (2026-08-03). Over 40 s the title makes 1,758,140
// allocations and 1,229,146 frees, i.e. it really does retain a large share of
// what it takes -- this is not "nothing is ever freed". The deallocator is
// eboot+0x12af0 (rdi = pointer, dispatched through the allocator's vtable slot
// +0xa8, falling back to 0x19a50 to find the owner); profile it with the `:c`
// suffix, which ranks by call count instead of by a first argument that is not
// a size:
//   +DELTA_HEAP_PROF=0x201400012820,0x201400012af0:c
// What that still cannot say is WHICH site's memory is retained, because a
// free is called from a destructor rather than from the allocating code. The
// tool that would settle it is live-bytes-per-site, which needs the allocation
// pointer and so needs the allocator's RETURN hooked, not its entry.
//
// THE HEAP: the scoped-allocator routing is RULED OUT (2026-08-03). The 4.1 MB
// per-frame render surfaces at eboot+0x91906 go through allocator class 1,
// which 0x12820 takes from a thread-local stack of scopes pushed by 0x12300
// and popped by 0x12350 (entry stride 0x20, depth at [block+0x400]), falling
// back to the process heap when that stack is empty. Measured with
//   +DELTA_HEAP_PROF=0x201400012820 +DELTA_HEAP_PROF_SCOPE=0x2014015fff98:0x400
// (SIGUSR1 to dump): 0x91906 reports [scoped] for every one of its calls, so
// those surfaces are NOT leaking through the unscoped fallback. Note the
// probe must use the backend's guest fs base, not the thread's real one --
// the lifter rewrites guest fs accesses, so ARCH_GET_FS reports the HOST base
// and made an earlier run of this measurement read zeros everywhere.
//
// Skip CGame::LoadInitialWorld's gate: no crash, but nothing to draw either.
// +DELTA_SOTC_SKIP_WORLDWAIT=1

// THE FRAME, MAPPED (2026-08-04, with tools/gpu_capture.py -- see
// delta/gpu/DEBUGGER.md). SotC is a deferred renderer: shadow cascades ->
// main-view Z-prepass (reverse-Z, clear 0, ZFUNC=GEQUAL) -> 7-MRT G-buffer
// re-drawing the same geometry with ZFUNC=EQUAL -> deferred lighting (samples
// the G-buffer AND the depth buffer it has bound) -> a full-screen compute
// resolve that publishes the scene colour -> half-res post -> tonemap -> UI
// layer -> composite. Three defects were deleting most of that and are fixed:
// the 16 MiB vertex ring declined 83 draws a frame (now 512 MiB), the EQUAL
// depth test rejected the scene because our two vertex shaders are not
// bit-identical (DELTA_GPU_RELAX_ZEQUAL, on by default), and the lighting pass
// was declined as self-sampling (now bound DEPTH_READ_ONLY).
//
// The integer G-buffer is now implemented (DELTA_GPU_INT_RT=1, opt-in): all
// seven targets carry real world geometry, where two of them used to read
// exactly zero. The next break is one stage on -- the deferred lighting pass
// discards nearly every pixel because it samples its material/stencil ID from
// the draw's own stencil surface (0x805fe50000, R8_UINT), and we have no
// stencil-aspect sampled view, so that binding resolves to an unrelated colour
// RT. Needs ResolveSampledStencil + a VK_IMAGE_ASPECT_STENCIL_BIT view.
//
// WHY IT WAS BLACK BEFORE THAT: the G-buffer is an INTEGER buffer.
// CB_COLORn_INFO says FORMAT=COLOR_32 / COLOR_32_32 with NUMBER_TYPE=UINT for
// 6 of the 7 targets, and CB_SHADER_MASK=0x1331111 agrees (one component per
// 32-bit target). We create them B8G8R8A8_UNORM, so two read back exactly
// zero and the scene the compute resolve publishes is black. The integer path
// is implemented but gated off -- with it on the title stops issuing the
// G-buffer pass altogether, which is not yet understood.
// +DELTA_GPU_INT_RT=1                    integer colour targets (UNVALIDATED)
// +DELTA_GPU_RELAX_ZEQUAL=0              restore the strict EQUAL depth test
// +DELTA_GPU_VBRING_MB=<n>               override the vertex ring
// +DELTA_GPU_CAPTURE_AFTER=150 +DELTA_GPU_CAPTURE_DIR=/tmp/cap   frame capture
// +DELTA_GPU_TSCAN=<surface> +DELTA_GPU_TWATCH=1   descriptor archaeology
// +DELTA_GPU_NOMRT=1 +DELTA_GPU_CBINFO=1  colour-target binding

// ROOT CAUSE LEAD (2026-08-04): the descriptor pool at 0x8052xxxxxx is the
// TITLE'S OWN HEAP -- DELTA_GUEST_WHIST=8052000000:1000000:400 names the writer
// as Shadow_Shipping+0x48f07 (from +0x48ec5), which disassembles as malloc
// chunk bookkeeping. The SRT points at a descriptor table the title has already
// freed, while a fresh copy sits ~6 MiB away. That is a guest lifetime bug, and
// one that reproduces every frame is usually something the emulator caused.
// Next step is the allocator hook, not the renderer.

// THE MENU CRASH (2026-08-06): the heap-corruption SIGSEGV in the title's
// malloc at Shadow_Shipping+0x48ac5 is DELTA_GPU_CS_SKIP_UPLOAD writing stale
// staging back over CPU-owned guest memory. First seen over the allocator's
// static bin array in module .data (float garbage at module+0xfacff0); the
// dmem-only restriction (commit "the upload skip must not cover module
// .data") moved the corruption, not removed it -- next crash was the same
// malloc walk over a FIBER STACK in dmem (rax=0x830a79fbd0, libSceFiber in
// the backtrace). The plan's "written, never read" does NOT imply "writes
// every byte", and the title keeps fiber stacks and heaps in the same dmem
// the material arenas live in. LEAVE THE KNOB OFF for this title until a
// write-coverage-tracking version exists; without it a full hour scripted
// through the menu runs crash-free (costs ~45-60 ms/frame of staging-in).
//
// PAST THE TITLE (2026-08-06): the menu opens and renders readable entries
// (New Game / Settings / Image Gallery, difficulty select) on current
// builds; the earlier "solid glyph blocks" existed only pre-dedupe.
//
// THE NEW-GAME CRASH, DIAGNOSED (2026-08-06): confirming New Game dies
// deterministically -- SIGSEGV at Shadow_Shipping+0x48ac5, same registers
// every run, with AND without the upload skip (the knob A/B above was a red
// herring: the surviving run had merely never confirmed the menu). The
// faulting function (prologue 0x48a70) INSERTS a block into a size-ordered
// free list whose nodes live INSIDE the freed blocks, and the pool's blocks
// are FIBER STACKS: the crashing thread's own rsp sits on the block whose
// node it is walking. A fiber returns its stack to the pool and KEEPS
// RUNNING on it; its calls trash the in-block node; the next insert walks
// garbage. DELTA_GUEST_WHIST=830a79f000:1000:200 census: the page's top
// writer is libSceFiber+0x381 (fiber context saves). Suspect: the shipped
// libSceFiber.sprx's exit/switch ordering (stack release before the actual
// context switch). No in-repo source -- next step is disassembling the sprx
// and comparing sceFiberReturnToThread/Finalize semantics against retail.
