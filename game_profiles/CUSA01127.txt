// P.T. (CUSA01127, PS4)
// FOX engine. Boots, loads and runs its full render graph: ~223 draws/frame at
// ~23fps, every shader translates, no draw declines. Assets stream fine
// (/app0/texture.qar and /app0/chunk1.psarc read correctly through the PFS).
//
// THE SCENE RENDERS (2026-08-01). The hallway is present in the G-buffer once
// the vertex layout comes from the fetch shader rather than from buffer loads
// in the shader body. Present it with
//   +DELTA_GPU_PRESENT_ADDR=0x8143800000
// to see it. The exposure chain works off it too.
//
// The presented frame is still black, and exactly one thing causes that: the
// 16x16x16 colour-grading LUT volume. A pass bakes it into a 256x16 strip and
// the tonemap samples that strip, so the strip's contents ARE the screen: when
// the volume bound a white fallback the screen was solid white, now that it
// binds real memory the screen is solid black. That memory (16 KB, tiling 19)
// is zero for the entire run: DELTA_GPU_TEXWATCH scans the whole surface and
// reports first_nz=-1 every frame.
//
// The LUT is not special. EVERY streamed guest texture is zero, and the reason
// is a missing staging->video-memory copy:
//  - The title takes two direct-memory pools: 0x30000000 at physOffset
//    0x3c800000 (memType 0, ONION) and 0xb0000000 at 0x6c800000 (memType 3,
//    GARLIC, mapped at 0x80a5100000). Every sampled texture and render target
//    lives in the Garlic pool.
//  - DELTA_GUEST_POPCNT over that pool: written bytes stop at pool offset
//    ~0x63c1bd9 (~100 MB). Everything the title samples from 0x811a.. upward
//    (the LUT, and the 20 streamed textures in 0x811ce00000+0x300000) is zero
//    for a 260 s run, so it is not a "still loading" race.
//  - The textures that DO have content (e.g. 0x80a6804000, first_nz=2) sit in
//    that low 100 MB and are uploaded during engine init.
//  - DELTA_QARBUF: /app0/texture.qar payloads (689 reads >= 64 KB) are read into
//    a ~1 MB ring in the ONION pool at 0x804fa24000. POPCNT there reports ~53%
//    of bits set and moving, i.e. live packed asset bytes.
//  So the chain is qar -> onion ring (full) -> MISSING -> garlic surface (zero).
//  Ruled out as the missing step: CP DMA (all 200 traced DMA_DATA packets are
//  src==dst shader prefetches, zero real copies), compute (CSRES lists only 3
//  dispatches, all in 0x80a6..), async compute queues (sceGnmDingDong is never
//  called), a second mapping of the same physOffset (each physical offset is
//  mapped exactly once), and a later MAP_FIXED over the pool (none).
//  Done with DELTA_GUEST_WPROT: the uploader is a plain libc memcpy
//  (libc+0x45a3e), and it only ever fills the low ~104 MB of the pool.
//  DELTA_GUEST_WPROT=811a300000:100000:4000 over 95 s of gameplay records ZERO
//  writes, so the guest never writes the region its own descriptors point at.
//  The title places its streamed texture heap ~1.8 GB into the video pool
//  (0x811a398000 is pool offset 0x75298000) while its uploads stay in the first
//  104 MB. Render targets at 0x8135..0x814b (~2.3 GB in) are fine because the
//  GPU writes those. So the open question is why the guest allocator hands out
//  surfaces at ~1.8 GB that its own upload path never targets: suspect
//  something we report to the allocator (pool base, size query, or a physical
//  offset) rather than anything in the GPU layer.
//
// Known gap found on the way, not yet fixed: a compute dispatch copies a
// 2048x1024 R8 image and we have no 8-bit single-channel format in the compute
// image list, so it zero-fills (DELTA_GPU_CSRES names it). Adding dfmt 1
// naively crashes, so the staging path needs care.
//
//  - Not the cause: depth test, face culling, the colour write masks, the
//    render-target size aliasing, missing assets, or shader translation.
//  - The colour-grading LUT (a 16x16x16 volume) gates everything downstream of
//    the tonemap: whatever it samples becomes the whole screen. Its guest
//    memory stays zero for the entire run, and nothing we emulate writes it.
//    Investigate that only after the G-buffer produces pixels.
